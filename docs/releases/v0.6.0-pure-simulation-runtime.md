# v0.6.0-pure-simulation-runtime GitHub Release Note

Release title:
`v0.6.0-pure-simulation-runtime — Pure-Simulation Full-Stack Runtime Integration`

Tag: `v0.6.0-pure-simulation-runtime`

Target commit: `b80cd1e Add GWM simulation closed-loop demo`

## Summary

This checkpoint completes Phase 6 pure-simulation runtime integration. It moves
the project beyond mock-only readiness into guarded simulation / SITL wiring for
Isaac Sim / Isaac Lab, ROS2 sensor synchronization, MAVSDK, PX4 SITL command
validation, and the Generated World Model / WAM-style closed-loop demo.

The release remains simulation-only. It does not enable real hardware flight,
autonomous real flight, automatic PX4 launch, Nav2 integration, certified
safety, or production readiness.

## Phase 6 Highlights

- Phase 6-A: Pure Simulation Runtime Profile
  - Added the explicit `pure_sim_isaac_px4_ros2` runtime profile, safe refusal
    rules, required operator gates, and setup documentation for the intended
    Isaac Sim / ROS2 / PX4 SITL / MAVSDK stack.
- Phase 6-B: Isaac Sim / Isaac Lab Sensor Runtime Execution
  - Added a guarded Isaac sensor runtime runner that can launch or attach to
    Isaac when explicitly gated, read virtual sensor snapshots, convert them to
    `SensorObservation`, and close owned resources cleanly.
- Phase 6-C: ROS2 Simulation Sensor Bridge
  - Added a simulation-only ROS2 sensor bridge path for RGB, depth, LiDAR, IMU,
    and odometry synchronization through `ROS2SensorSynchronizer`.
- Phase 6-D: PX4 SITL + MAVSDK Command Validation
  - Added guarded PX4 SITL command validation using `MAVLinkBridge`,
    `ControlCommand`, and `ControlBarrierFunction`, with fake-client tests by
    default and externally managed PX4 SITL only.
- Phase 6-E: Isaac + PX4 SITL Closed-Loop Bridge Design
  - Added a design and dry-run readiness report for Isaac/PX4 state ownership,
    timing, command paths, coordinate-frame policy, failure handling, and
    refusal rules.
- Phase 6-F: GWM / WAM Closed-Loop Simulation Demo
  - Added the guarded Phase 6-F demo that connects simulated observations,
    `ObservationBuffer`, GWM/WAM rollout, candidate scoring, CBF safety
    filtering, and MAVSDK/PX4 SITL command history into one pure-simulation
    loop.

## Safety Defaults

Deployment remains locked down by default:

```yaml
deployment:
  mock: true
  sitl_enabled: false
  real_hardware_enabled: false
  autonomous_real_flight_enabled: false
```

Pure simulation / SITL profiles may opt in to:

```yaml
deployment:
  mock: false
  sitl_enabled: true
  real_hardware_enabled: false
  autonomous_real_flight_enabled: false
```

Live runtime paths remain guarded:

- Isaac runtime requires `GWM_ALLOW_OPTIONAL_RUNTIME=1` and
  `GWM_RUN_ISAAC_RUNTIME_TESTS=1`.
- ROS2 simulation sensor sync requires `GWM_ALLOW_OPTIONAL_RUNTIME=1` and
  `GWM_RUN_ROS2_SENSOR_SYNC_TESTS=1`.
- MAVSDK / PX4 SITL command validation requires
  `GWM_ALLOW_OPTIONAL_RUNTIME=1`, `GWM_RUN_MAVSDK_SITL_TESTS=1`, and
  `GWM_ALLOW_SITL_COMMANDS=1`.
- PX4 SITL must be started externally by the operator. This release does not
  use automatic PX4 launch.

## Known Limitations

- No real hardware flight validation.
- No autonomous real flight.
- No formal CBF certification proof.
- No production-readiness claim.
- No automatic PX4 launch.
- No Nav2 integration.
- Optional Isaac / ROS2 / MAVSDK / PX4 SITL runtime paths are guarded opt-ins
  and are not required for normal tests.
- The Phase 6-F fake-mode demo is an integration wiring check, not a navigation
  performance claim.
- Runtime reports, logs, bags, SITL artifacts, screenshots, datasets,
  checkpoints, and `outputs/` artifacts are machine-specific and should not be
  committed.
